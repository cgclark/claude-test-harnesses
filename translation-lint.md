# Translation lint

> Lets Claude check every translation in every language against rules a machine can verify (same arguments as the English, glossary words kept, markup that renders, no text that bypasses localization, generated text unchanged from a blessed baseline), so "26 languages complete" means correct, not just filled in.

**Applies to:** apps with a String Catalog (`.xcstrings`) or any key → translation table, games whose engine reads
its own string tables, and rule-generated text (bot chat, templated messages) · **Needs:** Python 3, the catalog as
JSON, the source tree for source-level checks; a way to run the app in a language for the on-screen check

## Why it exists

By default Claude translates strings, Xcode's catalog shows every language at 100%, and the work is reported done.
"Complete" in a catalog means translated, not correct, and many failures only show on screen or at run time:

- A Japanese translation picked up a `%lld` from a sentence with no numbers. iOS read an argument that was never
  passed. The catalog reported nineteen languages complete.
- Grammar-agreement markup (`^[%lld ride](inflect: true)`) built into a plain `String` went to the screen raw. It
  shipped three times; the unit tests passed each time because the string value was correct.
- `Text("a " + "b")` and `.formatted()` without the app's locale produced English, or the phone's language, on a
  German screen.

Built for a fitness app in 26 languages, including right-to-left, and a game port in 24 languages whose menus are a
fixed 640×480 layout. The game's bot chat is generated by grammar rules, so a rule change can alter thousands of
lines at once.

## What it does

1. **Catalog checks** walk every key × language (including plural and device variations) and fail on: a
   placeholder multiset that differs from the English, a glossary `keep` word lost, a banned word present, a
   glossary term rendered differently when it stands alone, a tab or newline in a one-line table, an ALL-CAPS menu
   item translated to mixed case. They report, without failing, a term inside a sentence that may be inflected,
   menu items over 1.6× the English length, and coverage per language.
2. **Source checks** scan the code for text that escapes localization: joined literals, locale-less formatting,
   inflection markup passed to an API that returns it raw, and literals not yet triaged into the catalog.
3. **Generated-text regression:** regenerate every output and diff it against a blessed baseline; `bless` only after
   the diff is reviewed.
4. **Pool checks** hold hand-written per-language line pools to the events and slots the engine fills.
5. **On-screen check:** launch the build in a language, capture the screen, and look at the result.

Every script prints one line per problem and exits 1 on any failure.

## Recipe

**1. Keep a glossary as data** (`tools/glossary.json`), with an `_about` paragraph for translators:

```json
{ "keep":   ["<AppName>", "<BrandWord>"],
  "terms":  { "<Feature name>": { "de": "<rendering>", "fr": "<rendering>" } },
  "banned": { "en": ["<word>"], "de": ["<word>"] },
  "rules":  ["<what each word means and when to use it>"] }
```

**2. Placeholder check.** Compare argument types as a multiset, so positional reordering (`%1$@`, `%2$lld`) passes:

```python
SPEC = re.compile(r'%(?:(\d+)\$)?(lld|@|\d*\.?\d*f)')
shape = lambda s: sorted(kind for _, kind in SPEC.findall(s))
for lang_file in glob("tools/translations/*.json"):
    for key, value in json.load(open(lang_file)).items():
        if isinstance(value, str) and shape(key) != shape(value):
            print(f"{lang}: {key!r} English takes {shape(key)}, translation takes {shape(value)}")
```

For a C-style engine, widen the pattern to `%[-+ #0]*\d*(?:\.\d+)?[sdifcuxXeEgG@]`, treat `i` as `d`, and compare
in consumption order sorted by position.

**3. Glossary check.** For each catalog value: every `keep` word in the key must appear in the value; no `banned`
word may appear (whole-word match in spaced scripts, substring in Japanese, Chinese and Thai); a key equal to a term
must equal its rendering. Bound `keep` matches by Latin letters and digits only, because in CJK and Thai a kept name
sits directly against the surrounding text and `\w` would reject a correct translation. Run it over the web page's
string table too if the site shares the copy.

**4. Source checks** over `Sources/**/*.swift` (skip comments and generated files):

```python
joined  = re.compile(r'(Text|Label|Button|LabeledContent)\(\s*"(?:[^"\\]|\\.)*"\s*\+')   # never harvested
inflect = re.compile(r'\^\[[^\]]*\]\(inflect:')    # inside (?<!Attributed)String(localized: ...) = shown raw
# and: every .formatted(...) call must pass the app's locale (here a `.inApp` helper) unless it formats for machines
```

**5. Run the set** after any string change:

```bash
python3 tools/check-placeholders.py && python3 tools/check-glossary.py \
  && python3 tools/check-inflection.py && python3 tools/check-strings.py
tools/l10n/check.py                 # engine tables: placeholders, keep, capitals, table safety, length, coverage
tools/l10n/check.py --draft <lang>  # a translator's draft file, checked as if applied; catalog untouched
tools/l10n/harvest.py --check       # fails while new interface literals are untriaged
```

**6. Generated text against a baseline.** Generate every bot's (or template's) output per language to TSV, diff one
column against `build/<gen>/baseline/`, and copy into the baseline only after reading the diff:

```bash
tools/l10n/<gen>/dev/check.sh            # regenerate + diff; prints "== <bot>" and the changed lines
tools/l10n/<gen>/dev/check.sh regen      # rebuild the English corpus and tags first
tools/l10n/<gen>/dev/check.sh bless      # accept: copy current output into the baseline
python3 tools/l10n/<gen>/dev/poolcheck.py [--lang <code>] [<bot> ...]
```

`poolcheck.py` reports per bot: lines, events covered, and the share of English lines that have a usable pool line
(one that uses only slots that event fills). It fails on placeholders that differ between a line and its voiced
variant, events the bot does not have, slots the event never fills, a name with a grammatical ending attached,
stray braces, and over-long lines.

**7. Look at it on screen.** For the fixed-layout menus, launch the build in a language and capture it. In the game
this goes through the engine console (see [game-console-driving](game-console-driving.md)):

```bash
tools/buttons/live-check.sh <lang> <out.png>     # sets the language for this run only, opens the menu, grabs, quits
```

Read the PNG. The length report from step 5 says which screens to open.

**8. Line breaks in space-less scripts.** For long text in Japanese, Chinese or Thai, a dev-time annotator inserts
U+200B at word boundaries (Apple `NLTokenizer`) with kinsoku guards, so wrapping falls on words:

```bash
echo "<Japanese sentence>" | swift tools/breakannotate.swift --debug   # prints breaks as ·
```

## Traps

- **Changing what a line says.** Fixes change how a line is said, never what it says: no detail the original lacks,
  no joke swapped for a "better" one. Reviewers briefed to "replace lines that don't land" produced 397 edits that
  had to be discarded. Brief review agents to bring a line back to the original, not to rewrite it.
- **"Complete" is not correct.** Coverage counts filled values. Only the checks above count errors.
- **Positional forms are not mismatches.** `%1$@` and `%@` are the same argument; reordering is the translator's job.
- **Inflection markup needs a renderer.** Only `Text(LocalizedStringKey)` and `AttributedString` agree it.
  `String(localized:)` returns the markup as-is. Lint the source; tests on the string value cannot see it.
- **Keyed strings are not extracted.** `String(localized: "some.key", defaultValue:)` must be added to the catalog by
  hand (`extractionState: manual`).
- **Engines that draw text as written.** The game upper-cases only untranslated text, so a mixed-case translation sat
  among capitals. Hence the capitals rule.
- **Strings built at run time are not keys.** A joined or interpolated string never matches a table entry. Make it
  one literal or translate the parts. Logging untranslated lookups on the device (`lang-missing-<code>.txt`) finds
  keys that drifted from the code.
- **Right-to-left names.** Wrap each `%@` in FSI/PDI isolates for Arabic and Hebrew in one pipeline step, rather than
  at call sites.
- **Blessing to make a diff go away.** The baseline changes only after the diff has been read and the change was
  intended.
- **Simulator preferences.** `simctl spawn … defaults write` does not reach a running app's preferences (cfprefsd
  cache). Change the language through the app's own UI or launch arguments (`-AppleLanguages "(de)"`).

## What it does not cover

Whether a translation reads naturally, keeps the register, or is accurate beyond the glossary. Agent reviews and
on-screen checks cover part of that; the lint only proves the mechanical rules. Layout in every language on every
screen still needs screenshots, and right-to-left mirroring needs its own pass in forced RTL.

## Loading this into Claude

> After any string or translation change, run the localization checks and report their counts:
> `check-placeholders.py`, `check-glossary.py`, `check-inflection.py`, `check-strings.py` (or `tools/l10n/check.py`
> for the engine tables) must all exit 0. Generated text is diffed with `check.sh`; run `check.sh bless` only after
> reading the diff and confirming the change was intended. Never report a language as done from catalog coverage.
> Fixes change how a line is said, never what it says.
